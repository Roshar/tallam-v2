# Базовая защита входа

## Что уже было

- Пароли хранятся в bcrypt (cost 10), сравнение через `bcrypt.compare`.
- На неверные данные - одинаковый ответ «Неверный логин или пароль», без подсказки, существует ли аккаунт.
- При успешном входе сессия пересоздается (`req.session.regenerate`), защита от фиксации сессии.
- Cookie: `HttpOnly`, `Secure` в production, `SameSite=Lax`.
- `app.set("trust proxy", 1)` - реальный IP клиента за nginx.
- Аккаунты со статусом `off` не пускаются.
- Все попытки входа пишутся в аудит, включая неудачные (`auth.login`, статус `failure`).
- Восстановление пароля: captcha и лимит запросов с одного IP.

## Ограничение перебора

Добавлено в ноябре 2026 после аварии.

### Приложение

`backend/src/middleware/login-rate-limit.ts`, подключен к `/api/auth/login` и `/api/accountant/login`.

- 10 неудачных попыток за 15 минут на пару «IP + логин»;
- 50 неудачных попыток за 15 минут на IP (перебор по разным логинам);
- считаются только ответы 401; успешный вход сбрасывает счетчик пары «IP + логин»;
- при превышении - 429 и JSON `{"error":"Слишком много попыток входа. Попробуйте позже."}` с `Retry-After`;
- счетчики в памяти процесса. У нас один процесс PM2, при рестарте счетчики обнуляются - для базовой защиты допустимо.

### Nginx

Файл `/etc/nginx/conf.d/login-rate-limit.conf`:

```nginx
map $uri $login_limit_key {
    default "";
    /api/auth/login $binary_remote_addr;
    /api/accountant/login $binary_remote_addr;
    /api/login $binary_remote_addr;
}

limit_req_zone $login_limit_key zone=login_limit:10m rate=30r/m;
limit_req_status 429;
```

В `location /api/` сайта tallam и в `location /` сайта taskflow добавлено:

```nginx
limit_req zone=login_limit burst=15 nodelay;
```

Для остальных URI ключ пустой, поэтому ограничение на них не действует. Nginx ловит всплески (например, скрипт с 20 запросами), приложение - точечный подбор пароля.

## Как проверить

1. 10 раз войти с неверным паролем - ответы 401, 11-й - 429 с сообщением.
2. С другого логина с того же IP вход не блокируется (лимит по паре, не по IP).
3. `/api/health` и остальные страницы не ограничиваются.
4. Через 15 минут счетчик сбрасывается; рестарт API тоже обнуляет счетчики.
5. В аудите видны неудачные попытки с email и IP.

## Ограничения и что дальше

- Счетчики в памяти: рестарт сбрасывает, распределенный перебор с разных IP не остановит полностью (но лимит на пару «IP + логин» и аудит помогают).
- Captcha на входе не включена; при необходимости можно переиспользовать captcha восстановления пароля после 5 неудач.
- 2FA для админа не включена.
- fail2ban сейчас банит только SSH; веб-правило можно добавить отдельно.
